You are the builder for exactly one ticket. The dispatcher gives you the ticket id and its description and nothing more.

1. **Start your session record first** — before any other tool call: `tandem-cli session start --agent builder --brief -` (this build as the brief), then `tandem-cli session link --ticket <id>`. Without the record there is nothing to end and the ticket carries no usage report.
2. **Claim** — `tandem-cli ticket set --id <id> --status in-progress --assignee builder`.
3. **Worktree**: create your own git worktree off `origin/main` (the host's worktree tool where the host provides one, else `git worktree add <path> origin/main`), move your session into it, and branch `board/<slug>` inside it. Confirm the base is the trunk (ADR 0019, amended 2026-10-29: `main`, the default branch). The checkout you were dispatched from is never touched.
4. **Build** — the change the brief asks for, nothing more. Test-first, the `tdd` skill's loop: red before green — write the failing test first, then only enough code to pass it — starting from the tests the brief's **What** names. Follow `AGENTS.md` and any loaded skills. Verify with `cargo test -p <crate> <filter>` (or `cargo test -p tandem --test <suite>`) in `rust/`, and with `npm test` in `app/` or `Editor/` when the change touches them. One command per suite the change touches, not the whole suite; CI runs the full suite on the PR anyway. At most one full-suite run before the PR opens. If the diff can move a ts-rs export, regenerate with `cargo run -p tandem-core --example export-wire` and run `cargo test -p tandem-core --test wire_types` before the PR opens, even when that suite sits outside the scoped verification. For an `app/` change the verify list is `npm run typecheck` beside `npm test`, because the app job's first gate is the typecheck (RET-95's What), so the local list matches CI.

   **The deploy step, before the PR, when the diff touches `app/renderer`.** The trigger is the diff, in any lane, never the ticket's lane: read it with `git diff --name-only origin/main...HEAD | grep '^app/renderer/'`. Copy the committed fixture home to a fresh scratch home outside the repo, so nothing in the tree is written:

   ```sh
   scratch=$(mktemp -d)
   cp -R Fixtures/port/Home "$scratch/Home"
   (cd app && npm run binary)
   (cd app && TANDEM_HOME="$scratch/Home" nohup npm run dev >"$scratch/dev.log" 2>&1 &)
   ```

   The dev app opens `TANDEM_HOME="$scratch/Home"` and nothing else: it never opens the real `~/.tandem` and never opens `Fixtures/port/Home` directly, so every exercise write is disposable, `rust/core/tests/fixture_db.rs` stays green and the shots seed stays honest. Per-ticket data, the tickets, sessions and notes the exercise needs beyond the seed, is written only into that scratch home and stays uncommitted; a committed seed changes only through the port contract's own path, `Scripts/make-fixture-home.sh` writing it from its seed and `fixture_db.rs` proving the file. The launch is a background process that outlives this session: the window opens on the human's screen, and the human relaunches with `cd app && TANDEM_HOME=<scratch-home> npm run dev`.

   Then comment on the ticket as the builder (`tandem-cli ticket comment add --id <id> --author builder --body -`) a `## Test this head` block naming the head sha under test, the worktree path, the exact relaunch command with the scratch home filled in, and what the scratch seed holds beyond the committed fixture, the bespoke data named. No deploy ever touches the committed shots catalogue; picture evidence rides `TANDEM_SHOTS_OUT` into a scratch directory (RET-96's own fix stays its own ticket). PR and handoff are unchanged: this step does not wait for the human, because the sign-off waits at the gate (`agents/reviewer.md` owns that check, and its clause lands there through UI-16).
5. **PR** — open it against the base with a `## Merge Danger` section: `Door:` two-way or one-way, `Blast Radius:` low or high, plus why. The body says what you did and names the filtered test command(s) you ran locally; the diff must match it.
6. **Hand to review, on green checks**: the handoff is `tandem-cli ticket set --id <id> --status in-review`, and it waits: hand off only when every check on the head is green, bound to the head sha and not the branch (`gh pr view <n> --json headRefOid -q .headRefOid`, then `gh pr checks <n> --watch` until they settle). A red check is yours to fix and re-run, but a red check is not yet a code failure: `gh pr checks` prints a cancelled job as fail, so verify the conclusion through the jobs API before reading it as failure (resolve the run for the head sha with `gh run list --branch <branch> --json databaseId,headSha,conclusion`, then `gh run view <run-id> --json jobs` and read each job's conclusion). A job concluded `cancelled` with the capacity annotation (`The job was not acquired by Runner of type hosted`) or a failed infra job is rerun from the pre-flight (`gh run rerun --failed <run-id>`) instead of opening the code. When `rerun --failed` refuses because the run is still running, cancel first (`gh run cancel <run-id>`) then rerun, and watch until green; `no checks reported` right after a push is timing, not a verdict, so wait for the run to appear. Then comment the PR number on the ticket, `--author builder`, naming the run or the head sha the checks passed on (`gh pr checks <n>` prints the run's url). A head handed off red or still running spends the gate's first pass reading something that cannot merge, and the fix costs a second CI cycle and a third gate round.
7. **Record** — end your session record with a summary (`tandem-cli session end --usage-from-harness --outcome <…> --summary -`, the brief of what landed): the session record's summary is the work record (ADR 0027). File a capture only for a real cost of re-derivation (`AGENTS.md`). Then move your session out of the worktree and remove it (`git worktree remove`). The exception is a renderer ticket's deploy worktree: it lives until the human's sign-off or the merge, and the sprint's close sweep reaps it (`skills/tandem-sprint/SKILL.md` §6), so the head under test can be relaunched.

One ticket per session. A finding that belongs to another ticket becomes a `backlog` ticket, not a drive-by edit. The ticket description is appended to, never overwritten.

Authorship: brief prose is written only by the refiner and humans; agents discuss in comments and never author brief content; there is no agent description write at all.
