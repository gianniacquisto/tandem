# Rendered-markdown facts — Obsidian defaults, KaTeX, mermaid, WKWebView file access, CM6 prior art

Research for [ticket 05](../issues/05-rendered-markdown-feature-set.md). Date: 2026-10-15. Primary sources where possible (Apple docs, vendor docs, npm metadata); "community-verified" = forum/repo claims without a primary source. Facts only — decisions live in the ticket.

## 1. Obsidian stock "Live preview" feature set (no community plugins)

- **Math**: core, out of the box; `$…$` inline + `$$…$$` display. Engine is **MathJax, not KaTeX** — VERIFIED (official help): https://obsidian.md/help/advanced-syntax ("using MathJax and the LaTeX notation"); corroborated https://forum.obsidian.md/t/setting-options-for-katex-rendering/75190 ("They're using MathJax, see Credits").
- **Mermaid**: **core plugin**, not community (toggle: Settings → Core plugins). Added in Obsidian **0.7.6** (Jul 2020) — VERIFIED: https://x.com/obsdmd/status/1281301410890551296, https://forum.obsidian.md/t/mermaid-plugin/97782. **Off by default since Obsidian 1.13** — VERIFIED (official changelog): https://obsidian.md/changelog ("1.13 already introduced some new guardrails like Mermaid diagrams being off by default"). Bundled mermaid v11.4.1 as of 2025 — community claim: https://forum.obsidian.md/t/update-mermaid-js-from-11-4-to-11-5-or-later-to-fix-arrow-rendering/107507.
- **Images `![](assets/img.png)`**: markdown images render, resolved **against the vault** (shortest-unique / vault-root paths, not strictly note-relative) — community-verified: https://forum.obsidian.md/t/paths-with-space-break-the-markdown-parser/51967, https://designdebt.club/getting-an-embeds-full-file-path-in-obsidian. HTML `<img src=relative>` historically did NOT resolve (vault has no file base URL): https://forum.obsidian.md/t/embed-vault-images-via-html-with-relative-path/41770; relative `<img>/<video>/<audio> src` reportedly added in v1.8.1 — community claim (same thread).
- **Emoji `:smile:`**: **NOT stock** — community plugin (obsidian-emoji-shortcodes): https://forum.obsidian.md/t/enter-emoji-with-colon-notation-eg-smile/9619, https://github.com/phibr0/obsidian-emoji-shortcodes. VERIFIED.
- **Footnotes `[^1]`**: core (official help "Footnotes"): https://obsidian.md/help/syntax. Caveats: inline footnotes `^[…]` "only work in reading view, not in Live Preview" (help, VERIFIED); LP rendering of `[^1]` had a reported bug (v1.5.3): https://forum.obsidian.md/t/footnotes-are-not-rendered-in-live-preview-mode/75904; footnotes in tables not supported in LP (FR): https://forum.obsidian.md/t/live-preview-support-footnotes-in-tables/42738.
- **Sub/superscript `~sub~` / `^sup^`**: **NOT stock** — only HTML `<sub>/<sup>` or math; pandoc-style is an open feature request + community plugins: https://forum.obsidian.md/t/question-about-superscripts-and-subscripts/25941, https://forum.obsidian.md/t/pandoc-style-superscript-and-subscript/62369. VERIFIED (consensus + FR status).
- **Raw HTML**: inline/block HTML tags **are rendered in Live Preview** (with known gaps: HTML entities not rendered in LP, only Reading view; block-HTML bugs): https://forum.obsidian.md/t/render-html-entities-in-live-preview/30795, https://forum.obsidian.md/t/html-blocks-rendering-incorrectly-in-live-preview/32745. Scripts don't execute in preview (sanitized) — community claim, no primary source found.
- **Task checkboxes**: **interactive (clickable) in Live Preview** — plugin docs describe clicking the checkbox in Live Preview to toggle: https://publish.obsidian.md/tasks/Getting+Started/Getting+Started; LP renders a DOM checkbox (`.markdown-source-view.mod-cm6 .task-list-item-checkbox`): https://forum.obsidian.md/t/tasks-checkboxes-in-callouts-inconsistent-starting-positions-or-margin-between-live-preview-and-reading-view/74223. Community-verified.
- **`[text](note.md)`**: becomes an **internal link** (equivalent to wikilink): https://obsidian.md/help/links. VERIFIED.
- **Tables**: core: https://obsidian.md/help/advanced-syntax (VERIFIED). **Autolinks**: yes, GFM bare-URL autolinking on by default — community-verified: https://forum.obsidian.md/t/paste-urls-without-hotlink/95660.

## 2. KaTeX in a file:// WKWebView

- Pure client-side JS, no workers, no server calls — VERIFIED (official browser docs, self-hosted folder install): https://katex.org/docs/browser.
- Sizes (katex@0.19.0, measured 2026-10-15 from npm/jsDelivr): `katex.min.js` 272,868 B (≈74 KB gzip), `katex.min.css` 24,793 B (≈3.4 KB gzip), fonts 20×woff2 = 259,792 B (≈254 KB); woff (296 KB) and ttf (502 KB) also shipped. JS+CSS+woff2 ≈ 557 KB raw. Sources: https://registry.npmjs.org/katex (unpacked 4,043,696 B), https://data.jsdelivr.com/v1/packages/npm/katex@0.19.0, direct download measurements. VERIFIED.
- Fonts must be local, served from a `fonts/` dir **alongside the CSS** (relative `url("fonts/KaTeX_AMS-Regular.woff2")`); woff2 primary — VERIFIED: https://katex.org/docs/browser.
- Errors: `throwOnError` default **true → throws `katex.ParseError`**; if false, invalid source rendered in `errorColor` (default `#cc0000`) with hover text — VERIFIED: https://katex.org/docs/options, https://katex.org/docs/error.
- file:// incompatibilities: none found for co-located fonts. One community report of **Firefox 68+** blocking cross-origin fonts from `file://` ("CORS request not HTTP") — not WKWebView, not the co-located layout: https://sixthform.info/katex/guide.html. UNVERIFIED for WKWebView — smoke-test it.

## 3. Mermaid

- Sizes (mermaid@12.2.0, measured 2026-10-15): `dist/mermaid.min.js` = **5,494,801 B (≈5.2 MB) min; ≈1.51 MB gzip on the wire**. No fonts bundled (system fonts). Sources: https://registry.npmjs.org/mermaid, https://data.jsdelivr.com/v1/packages/npm/mermaid@12.2.0, CDN download measurement. VERIFIED.
- **Main thread, no worker required**: default `mermaid.render()` runs in-page and returns `{svg, bindFunctions}`; docs' usage pattern is parse-then-re-render: https://mermaid.ai/open-source/config/usage.html, https://labs.snyk.io/resources/exploiting-diagram-renderers. (A worker-based option exists in recent versions but could not be verified in current docs — UNVERIFIED.)
- file://: pure client-side, needs real DOM/layout; **no file:// failure reports found** — UNVERIFIED, no contrary evidence.
- Invalid/incomplete source: `mermaid.parse(text)` validates without rendering — returns `{diagramType}` if valid, **throws** if invalid (unless `suppressErrors`); `mermaid.parseError(err, hash)` is overridable; older versions rendered an error message inside the SVG (e.g. mkdocs-mermaid2 troubleshooting notes older versions "displayed nothing"): https://mermaid.ai/open-source/config/usage.html, https://mkdocs-mermaid2.readthedocs.io/en/latest/troubleshooting. VERIFIED (docs).
- Re-render per keystroke = known bad pattern: mermaid's own live editor has an open perf issue; proposed fix is debounce (0.5 s timer + dirty flag) with periodic catch-up render: https://github.com/mermaid-js/mermaid-live-editor/issues/891. VERIFIED. Obsidian's core-plugin debounce behavior: closed source, UNVERIFIED.

## 4. WKWebView file access (Apple)

- `loadFileURL(_:allowingReadAccessTo:)` — VERIFIED (Apple docs, retrieved 2026-10-15): `readAccessURL` = "the URL of a file or directory containing web content that you grant the system permission to read… To read additional files related to the content file, specify a directory." https://developer.apple.com/documentation/webkit/wkwebview/loadfileurl(_:allowingreadaccessto:) **Subdirectory access**: not stated explicitly in current Apple wording; directory-root (incl. subfolders) behavior is community-verified, e.g. EPUB loading from `OEBPS/` subfolders: https://swiftdevjournal.com/showing-local-html-content-in-a-wkwebview, https://github.com/NativeScript/NativeScript/issues/5227. Treat as community-verified.
- `WKURLSchemeHandler` — VERIFIED (Apple): protocol "for loading resources with URL schemes that WebKit doesn't handle"; register via `WKWebViewConfiguration.setURLSchemeHandler(_:forURLScheme:)`; respond with `didReceive(response:)`/`didReceive(data:)`/`didFinish` (may be called multiple times — WebKit engineer comment: https://bugs.webkit.org/show_bug.cgi?id=154916#c34). https://developer.apple.com/documentation/webkit/wkurlschemehandler, https://developer.apple.com/documentation/webkit/wkwebviewconfiguration/seturlschemehandler(_:forurlscheme:)
  - Gotchas: must be on the configuration the view is created with; "programmer error to call this method more than once for the same scheme"; can't register schemes WebKit handles (`https`) (Apple docs, VERIFIED). Cross-origin `fetch`/XHR to a custom scheme was blocked ("Cross origin requests are only supported for HTTP", WebKit source comment) — bug 201180 resolved as duplicate of **bug 205198 "Allow cross-origin requests to WKURLSchemeHandlers", RESOLVED FIXED**: https://bugs.webkit.org/show_bug.cgi?id=201180. Custom schemes are **not secure contexts** → an https page can't fetch them (mixed content): https://dev.to/alastaircoote/getting-wkwebview-to-treat-a-custom-scheme-as-secure-3dl3, https://bugs.webkit.org/show_bug.cgi?id=154916#c32. `<img>`/`@font-face` via custom scheme works (worked example): https://www.gfrigerio.com/custom-url-schemes-in-a-wkwebview.
- `file://` page → `https://` `<img>`: **no extra configuration; remote subresources load fine** — community-verified (WebKit bug 154916 context; "Remote resources are loaded without problem": https://github.com/NativeScript/NativeScript/issues/5227). `<img>` needs no CORS. UNVERIFIED in Apple docs — trivially smoke-testable.
- Related file:// limits (WebKit bug 154916, still **NEW**): XHR/fetch to `file://` fails; file:// images count as cross-origin (no WebGL textures); a WebKit engineer recommends `WKURLSchemeHandler` for 100%-local content: https://bugs.webkit.org/show_bug.cgi?id=154916.

## 5. CM6 live-preview prior art

- **Tables as real HTML `<table>` block widgets**: VERIFIED in open-source CM6 implementation "Atomic Editor" (MIT, Obsidian-style live preview): "a Table node's entire range is replaced with an interactive `<table>` widget" (StateField; contenteditable cells; structure-only `eq()`): https://github.com/kenforthewin/atomic-editor/blob/main/docs/architecture.md, https://news.ycombinator.com/item?id=48345201.
- **Block-decoration constraint**: "Images can't be emitted from a ViewPlugin because CM6 requires block decorations to come from a StateField or a mandatory facet"; image = block widget `side: 1` at `line.to`: same architecture doc. Same constraint in Obsidian's CM6: block decorations can't be specified via a ViewPlugin's `decorations` facet (RangeError) — use a state field: https://forum.obsidian.md/t/how-to-create-custom-codemirror-block-widget/36132. VERIFIED.
- **Checkboxes as widgets with click handlers**: task marker rendered as "a checkbox" widget; "- [ ] becomes a real, clickable checkbox" (atomic-editor README + architecture). Official CM6 ref: `Decoration` has `block?: boolean` ("block-level decoration. Defaults to false"); `WidgetType` has `block?: boolean` ("drawn between lines, or an inline widget (the default)") and `eventHandlers()`; official example shows a `CheckboxWidget` with `<input type=checkbox>`: https://codemirror.net/docs/ref/, https://codemirror.net/examples/decoration. VERIFIED.
- Obsidian itself: editor is CM6 (`.mod-cm6` selectors; "Obsidian's CodeMirror v6" in forum) — community-verified; its internal decoration mechanics are closed-source — UNVERIFIED beyond the forum thread above.
