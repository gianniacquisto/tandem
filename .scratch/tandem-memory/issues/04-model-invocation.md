# 04 - Model-invoked skill mechanics: discovery, description wording, global install

Type: research
Status: resolved (2026-10-17)

## Question

The destination skill (`skills/tandem-memory/` in this repo) must be model-invoked: the agent fires it on its own at the moments that matter (orienting at session start; recording highlights as work happens), with no human typing its name. Research against primary sources (OpenCode and Claude Code documentation and source):

1. **Discovery**: where each harness looks for skills — global and per-repo directories — and the file shape each requires (SKILL.md location, frontmatter fields); which frontmatter makes a skill model-invoked vs user-invoked in each harness.
2. **Invocation semantics**: when the harness loads a model-invoked skill's description into context, and how firing is decided; what description wording reliably fires on the two trigger branches (session-start orientation; recording work highlights) without spurious firing mid-task.
3. **Install/link**: how a skill stored at `skills/tandem-memory/` in this repo is best exposed globally for both harnesses — symlink vs copy, exact target directories, and what happens when the repo is updated.

Deliverable: a per-harness recommendation (discovery paths, required frontmatter, description-branch wording, install mechanism) with links to key sources. Capture the findings as a report on a throwaway `research/tandem-memory-model-invocation` branch (report file under `.scratch/tandem-memory/research/`), pushed but never merged, no PR.

## Answer

Model-invocation is the **default** in both harnesses — nothing special is needed; you only have to avoid the opt-out flags. **Discovery:** OpenCode v2 (this Mac runs v2.0.32) scans `~/.config/opencode/skills/` plus the compat roots `~/.claude/skills/` and `~/.agents/skills/` globally, and `.opencode/skills/`, `.claude/skills/`, `.agents/skills/` per repo walked up from cwd to project root, plus any `skills` array dirs in `opencode.json`; Claude Code scans `~/.claude/skills/` (personal, all projects) and `.claude/skills/` (project, start dir + parents to repo root), plus `--add-dir`/plugin/managed locations — both accept `<name>/SKILL.md` (OpenCode also a flat `<name>.md`) and both follow symlinks (OpenCode verified in source: `symlink: true` scan + realPath watching; Claude Code documented: "loads the skill once even if several locations point at the same target"). **Frontmatter:** spec-required `name` (kebab-case, must match the directory) + `description` make the skill model-invoked in both; the only switches that break model-invocation are `disable-model-invocation: true` (Claude — removes the description from context entirely) and `metadata.opencode/autoinvoke: "false"` / `disable-model-invocation: true` (OpenCode — hides it from the model's list), so set neither. Claude-only extras like `when_to_use` are safely ignored by OpenCode (tested: its v2 decoder silently drops unknown keys). **Description wording:** the description is the only always-loaded trigger surface (OpenCode renders it into an `<available_skills>` block in the system context each model step; Claude Code keeps it in a listing within a 1%-of-context budget), so it must scope-first, then name both trigger branches concretely — branch A phrased for what the model can detect at step 1 ("at the start of a session in a Tandem-tracked project — before reading or editing any project files — load this skill to orient from the bikeshed and pick up open threads"), branch B as named moments ("record a memory note when you make a non-obvious decision, discover a gotcha, finish a significant unit of work, or start/close an open thread; don't batch to session end") — because once the skill fires once, its body stays in context across turns in both harnesses and carries the record-as-you-go discipline; keep it ≤1,024 chars with the key use case first, and the one handoff variable is the scope marker for "Tandem-tracked" (e.g. Tandem MCP todos present vs. all local sessions). **Install:** two symlinks from the repo, no copy: `~/.agents/skills/tandem-memory` (OpenCode, matches the machine's existing convention) and `~/.claude/skills/tandem-memory` (Claude Code's only personal root; OpenCode also sees it but ID-dedups), so a repo update needs no reinstall — both harnesses watch the dirs and hot-reload mid-session; re-run the `ln -s` commands only if the repo is re-cloned to a new path.
