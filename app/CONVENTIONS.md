# The app's conventions

The idioms renderer code must match, so agent output looks like the app and not
like a tutorial. `docs/port.md` is the spec; this file is the house style. The
rules that can be checked are checked in `tests/` (tokens, the Node ban, the
colour ban, the preload surface), so a violation fails `npm test` rather than a
review.

## Layout

| path | what lives there |
| --- | --- |
| `src/main/` | the Electron process: the window, the rpc child, the policy |
| `src/preload/` | the one preload and its two-member bridge |
| `src/shared/` | types and constants both sides may name: the bridge, the policy |
| `renderer/src/` | React and TypeScript, no Node, no Electron |
| `renderer/src/shell/` | routing, tabs, the snapshot reducer |
| `renderer/src/faces/` | one file per face, one exported component each |
| `renderer/src/wire/` | generated by `ts-rs`; never edited by hand |
| `tests/` | the seams as vitest suites, one file per rule |
| `tests/shots/` | the screenshot suite: one Playwright spec, one scene |
| `shots/` | the suite around the specs: roots, seed, the scene manifest and the catalogue |

## The renderer is a browser

- No `electron`, no `node:` import, no `require`, no `process` in
  `renderer/src`. `tests/shell.test.ts` fails on any of them.
- The only window surface is `window.tandem`: `call({ method, params })` and
  `onChanged(listener)`. A third verb is a ticket on the protocol, not a wider
  bridge.
- A frame never reaches the renderer. `call` resolves with `{ reply }` or
  `{ error }`, the core's refusal with its `code` and `message`; a renderer
  narrows on `'error' in answer`. It never throws one: `contextBridge` clones
  the value it returns and rebuilds a thrown `Error` with the message alone, so
  the code would not arrive.

## Reading and writing messages

- **Read once, in the shell.** `App.tsx` owns the one effect that lists the
  board and re-lists on every change event. Faces receive props and call
  nothing.
- **Write through the same door.** A UI mutation uses a method the CLI also
  exposes, with a test that fails when a UI-only method appears. The method and
  its parameters come from `renderer/src/wire`, never from a hand-written
  shape.
- **The revision is the store's.** A listing's `revision` is what the shell
  displays; a change event is a hint to re-read, never a number to show.
- **A failed read keeps the last revision**, so the chrome does not claim the
  store moved when it did not.

## Components

- One component per file, named in PascalCase, exported by name: no default
  exports.
- A function declaration, not an arrow assigned to a const. Props type is
  `XxxProps`, declared above the component and exported when a parent needs it.
- Hooks at the top of the body, in a stable order. State is `useState` for
  local chrome and `useReducer` for anything with named transitions (see
  `shell/snapshot.ts`); no state library.
- A face is `Face` plus its own body. It does not draw its own header, its own
  tabs, or its own frame.
- Class names are `block__element`, with a state modifier only when the state
  is not already an attribute (`aria-selected` over a class).

## Styling

- **One token file.** Every colour, hairline, radius and motion duration, and
  every spacing step `Sources/Tandem/LigneTheme.swift` names, is a CSS variable
  in `renderer/src/tokens.css`, ported value for value. Layout arithmetic the
  Swift theme does not name (a tab's `8px` padding, a fact row's `12px 14px`)
  stays a literal in `app.css`; it is not a token.
- **No raw colour literals.** `#hex`, `rgb()`, `rgba()`, `hsl()` and `hsla()`
  appear only in `tokens.css`; a component, a face and `app.css` read
  `var(--ink)` and friends. `tests/shell.test.ts` enforces it.
- **Dark mode is the system's.** `tokens.css` carries a
  `prefers-color-scheme: dark` block; nothing forces one appearance, and no
  component branches on the scheme.
- **No inline styles.** Layout belongs in `app.css`.
- **Component styles go in `app.css`** under the component's block name. A
  second stylesheet appears when a face outgrows one screen, not before.
- Type is the system stack at 13 px; the chrome is 12.5 px and the face title
  15 px. No webfont.

## The Electron edges

- Security options live in `src/main/window.ts` and nowhere else:
  `contextIsolation`, `sandbox`, `nodeIntegration: false`, `webSecurity`,
  `webviewTag: false`.
- The window opens no remote content. A dev server is loopback only; any other
  origin throws before a window exists.
- `setWindowOpenHandler` denies every window, `will-navigate` refuses any
  origin but the loaded page, and `will-attach-webview` is prevented.
- One same-origin frame is admitted and it is ours: `editor-frame.html`, which
  loads the committed CodeMirror bundle. The policy's `frame-src 'self'` is the
  whole allowance; no remote origin can be framed, and the frame never opens a
  window or navigates the parent.
- The content security policy is `src/shared/security.ts`: the built page gets
  a meta tag, every response gets the header, and only development may admit
  the refresh preamble and the dev socket.
- No tray, no menu-bar extra: the app is window-first, and closing the window
  quits it.

## Tests

- Test the seam, not the rendering: the reducer, the route parser, the bridge
  surface, the spawn and its framing, the token port, the window options, the
  screenshot rule.
- A test lives in `app/tests/`, named for the unit it covers, and runs in Node.
  No DOM environment and no browser driver: the shell's state is plain data.
- The bridge's test cannot observe `contextBridge` in Node, so it enforces the
  seam's shape instead: a refusal is answered as data and still whole after
  `structuredClone`, the clone the bridge makes. Nothing that must survive the
  bridge is thrown.
- Run one suite while working (`npx vitest run tests/shell.test.ts`); CI runs
  all of them on three platforms.
