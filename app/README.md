# The app

Tandem's window: an Electron shell around the Rust core's `rpc` stream
(`docs/port.md`). The renderer holds no domain logic; every fact arrives over
the stream, and `app/CONVENTIONS.md` is the house style for everything drawn.

## Run it

```sh
npm ci
npm run binary   # builds rust/target/debug/tandem
npm run dev
```

Development spawns `rust/target/debug/tandem rpc` against the fixture home,
`Fixtures/port/Home`, unless `TANDEM_HOME` names another home. The Swift app
still owns `~/.tandem` until the cutover, so the shell never opens it by
accident.

`TANDEM_BIN` overrides the binary path. `npm run dev` reads the workspace
build; a packaged app reads the copy beside its resources
(`process.resourcesPath/tandem`, `tandem.exe` on Windows), and the artifact
carries it: `npm run pack` and `npm run dist` build the core in release
configuration and electron-builder copies it in.

## Checks

```sh
npm run typecheck        # the Node and the browser programs
npm test                 # the seams: tokens, bridge, spawn, window, shell
npm run build            # out/main, out/preload, out/renderer
npm run test:build       # the build-manifest guard, after npm run build
```

## The render path

The Bikeshed's Write surface draws math and mermaid from the renderer's own
dependency graph: `katex` (0.19.0) for an inline `$…$` run and a `$$` block,
`mermaid` (12.2.0) for a ` ```mermaid ` fence. There is no second editor, no
frame, no second build and no committed blob; `npm run build` is
`electron-vite build` alone.

Both libraries are lazy chunks (UI-24): `renderer/src/shell/lazy.ts` owns the
two dynamic imports and only the open note's parsed content calls them. A note
without a fence or math asks for neither, and the first paint shows the raw
source in the existing `.tandem-mermaid-error` / `.tandem-math-error` surface
until the chunk fills it in.

KaTeX's stylesheet is imported by the lazy KaTeX chunk
(`renderer/src/shell/katex.ts`), so Vite emits the 20 woff2 faces as assets
beside that chunk's CSS. `assetsInlineLimit` is 0 because `font-src 'self'`
stays: a face inlined as a `data:` URL would be a font the page cannot load.
`scripts/check-renderer.mjs` proves the one-page build, the 20 faces and the
absence of an inlined font; `tests/lazy-chunks.test.ts` reads the build
manifest and fails if either library returns to the entry's static graph.

The mermaid fence parity list (TAN-239) is the standing check:

- the strict security level, so rendering a diagram adds no network path;
- the theme repaint: a system scheme change re-renders mounted diagrams in the
  new palette (`prefers-color-scheme`, because the renderer paints dark from
  `tokens.css` rather than a `data-theme` attribute);
- the error fallback carrying the raw source under `.tandem-mermaid-error`;
- reveal-to-edit, where the caret in a fence shows its source and leaving it
  re-renders the diagram.

Math follows the same resting/editing split: a resting block draws KaTeX, and
the caret's block shows its source, so the row stays editable. A failed parse
shows the raw TeX in place (`throwOnError: false`). An opaque block, such as a
table or a raw HTML range, can be opened as raw markdown in place. The packages
and their verbatim licence texts are recorded in
`app/THIRD-PARTY.md`, generated by `scripts/third-party-notice.mjs`.

## Package

```sh
npm run dist
```

`electron-builder.yml` builds a dmg and a zip on macOS, an NSIS installer on
Windows and an AppImage on Linux. The zip is named `Tandem-<version>.zip`: the
tap's cask downloads exactly that path and `Scripts/bump-tap.sh` reads exactly
that name out of `SHA256SUMS`. `.github/workflows/app.yml` runs the same on the
three hosted runners and uploads one artifact per platform.

The artifact carries the core it runs: `scripts/prepare-binary.mjs` builds
`tandem` in release configuration, stages the agent face (`AGENTS.md`, `examples/skills/`,
`examples/agents/` and a `VERSION` marker) beside it, and electron-builder copies both
into the app's resources, so an installed app spawns nothing from a checkout. On
macOS an `afterPack` hook adds `Contents/MacOS/tandem-cli` as a symlink to the
core, the name the cask links and the skills call. The macOS arm64 dmg is about
118 MB, of which the core is about 6 MB.

Two gates check that. `npm run check:artifact` asserts the binary sits where
`src/main/binary.ts` resolves it and the face sits where `setup install` reads
it; `npm run smoke` launches the packaged app against a copy of
`Fixtures/port/Home` and requires `ticket.list` to answer a revision. CI runs
the second on macOS and Linux, under Xvfb on Linux.

**Code signing is not set up.** The artifacts are unsigned on all three
platforms: macOS ships with `identity: null` (no notarization), and Windows and
Linux are unsigned because no certificate is configured. Signing needs an
Apple Developer account and a Windows certificate, so it is left for the human
and filed as its own backlog ticket.

## A picture

The screenshots are `app/tests/shots/`, the one screenshot rig: one spec per
scene, one PNG per scene. A run writes its pictures to `app/shots-out/` and
never to `docs/screenshots/`; `npm run shots:publish` copies them into
`docs/screenshots/` and rewrites the catalogue there.

```sh
npm run binary
TANDEM_SHOTS_HOME=../Fixtures/port/Home npm run shots
```

`TANDEM_SHOTS_HOME` is required and must name a home under `Fixtures/`; a run
against `~/.tandem` is refused before a window opens, and the app opens a
scratch copy (`/tmp/tandem-shots/Home`) so the committed fixture is never
written to. Because that scratch root is one fixed path, a run takes an
exclusive lock on it (`shots/lock.ts`): a second run on the same machine waits
for the lock rather than reading or writing the same seed, and the two never
share one. The seed is that copy plus a fixed clock (`shots/clock.ts`) and a
fixed fixture user home, so a run writes the same picture it wrote last time. A
scene is one row in `shots/scenes.ts` and one spec in `tests/shots/`.
