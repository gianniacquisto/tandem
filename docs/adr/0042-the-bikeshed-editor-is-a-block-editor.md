# The bikeshed editor is a block editor over the markdown file

The bikeshed editor is a CodeMirror 6 inline live preview: raw markdown whose markers are hidden as the caret moves away, with tables, frontmatter and code tagged out of flow ([ADR 0012](0012-editor-formatting.md)). The human has decided the editor becomes a **block editor over the same `.md` file**. The file stays the source of truth and the editor never becomes one: every top-level block keeps its exact source bytes, and only a block the human actually edited is rendered from its model. Constructs the model does not cover, such as frontmatter, tables, raw HTML, display math and footnotes, survive by construction rather than by a per-construct case.

Decided 2026-11-09 (UI-17 built the model, the save seam and the round-trip gate).

## Decision

- **The file is the source of truth.** There is one `.md` per note, with no sidecar and no second stored shape. `note.write` remains the one write, so the model is a client-side view of the same bytes and this record adds no RPC method and no CLI verb.
- **The document is a total partition.** A document is an ordered sequence of gap parts and block parts whose concatenation is the source exactly. Blank lines and other trivia live in gaps, never inside a block's source, so editing a block cannot swallow a neighbour's spacing. A block's source is its parser node's exact range; whatever no node claims becomes an opaque block; nothing is dropped, trimmed or normalised. The invariant is `serialiseDocument(parseDocument(text)) === text` for any string, not only for well-formed notes. Line endings, a missing final newline, a BOM and trailing whitespace survive because they are source bytes.
- **What a block is.** The model owns: paragraph; heading with its level (ATX and setext both become a heading); list, ordered with its authored `start` or bullet, its items as child block sequences; task item with its checked state and child blocks; blockquote with child blocks; code, fenced or indented, with its info string as the language; thematic break; image (alt text, destination and title) when a top-level paragraph is exactly one image; and `opaque`, holding exact source. The kind names are the core view's (`heading`, `paragraph`, `list`, `code`, `quote`, `rule`, `task`) plus `image` and `opaque`, so the ticket sheet and the editor name the same things even though the parsers differ.
- **Opaque is one kind, not one per construct.** Frontmatter, a GFM table, a raw HTML block, a display-math block, a footnote definition and any range the parser does not claim are all `opaque` with their bytes. The construct's name is presentation, not model, until a ticket models it.
- **An edited block renders canonically; an untouched block never re-renders.** The serialiser emits each untouched block's source verbatim. An edited block is rendered from its model in one spelling per kind: ATX `## `, `- ` bullets, `1.` to `n.` from the list's `start`, `- [ ] ` and `- [x] `, a triple-backtick fence carrying its info string, `> ` per line, and `![alt](src "title")` for an image. Editing a setext heading therefore writes ATX, an edited `*` list writes `-`, and an edited indented code block writes fenced. That normalisation is confined to the edited block.
- **Inline content is one raw source string per block in this record.** Bold, italic, strikethrough, inline code, links, wikilinks and inline math become runs in UI-19, not here, so the model does not duplicate the inline dialect or normalise markers it cannot re-render.
- **The model lives in the renderer, in TypeScript.** `app/renderer/src/shell/blocks.ts` exports the document and block types and the pure operations `parseDocument`, `serialiseDocument`, `editBlock` and `documentBlocks`. The parser is `@lezer/markdown` 1.8.0 configured with the GFM pieces the editor's dialect uses (table, task list, strikethrough), plus frontmatter, display-math and footnote block scanners. Those scanners carry the editor bundle's rules (`Editor/src/pure/frontmatter.js`, `Editor/src/pure/math.js`) so a leading YAML fence and a `$$` block are recognised before the markdown tree splits them. The core's `markdown.blocks` stays the ticket sheet's reader; the corpus gate keeps the editor's dialect honest.
- **The splice is at the existing save seam.** `NoteBuffer` in `app/renderer/src/shell/note.ts` carries the parsed document: `openBuffer` parses the note, `applyDirty` re-parses the text the frame posts (the buffer's `text` stays the last posted text, so the echo check and the conflict banner are unchanged), `saveNote` writes `serialiseDocument(buffer.document)` and hashes those bytes for the conflict check, `arrival` and `takeTheirs` parse the body they adopt, and `keepMine` keeps the document. A serialisation failure returns the error state and surfaces in the banner; it never passes as a save.
- **A full parse per change is accepted.** Notes are small (the vault's largest is 46 KB) and an incrementally updated second block list would be a second truth this record does not need.
- **The gate is empirical.** `app/tests/fixtures/bikeshed-corpus/` holds synthetic checked-in notes, one construct per file plus kitchen-sink files, with a manifest the test loops. The same suite sweeps the repository's own markdown in place (`docs/adr/**/*.md`, `README.md`, `GLOSSARY.md`, `AGENTS.md`, `skills/**/*.md`, `agents/**/*.md`). Every corpus note and every repository file must serialise back to its exact bytes, every prefix and suffix of a corpus note must round-trip, and a one-block edit must leave every other part byte-identical.
- **The vault sweep is opt-in.** `Scripts/bikeshed-sweep.mjs` walks a directory given on the command line and reports each failing note by path and line only. It is read-only, never runs in CI, never writes, copies or prints note content, and is not wired into `npm test`.
- **The sequence.** UI-18 is the Write mode block surface and the caret model over this model and save seam. UI-19 adds inline runs, wikilinks and math. UI-20 adds the slash menu and drag reorder. UI-21 adds Source mode and the Write|Source switch. UI-22 retires the iframe and the editor bundle. UI-24 lazy-loads mermaid and KaTeX.
- **What stays until then.** Preview, CodeMirror 6, the iframe, mermaid and KaTeX are untouched by this record and keep working. The editor's conversion is incremental, and a half-converted surface is never the shipped path.

## Amendments

- **UI-21 (2026-11-10): the editor has two modes, Write and Source.** Write is the block surface and the preview; Preview is retired, so the note is either editable blocks or its raw bytes, never a second read-only rendering. A stored `preview` or `edit` reads as Write, nonsense reads as Write, an empty note opens Write, and any other note opens in the stored mode. The mode is one app preference persisted on an explicit switch, never on open.
- **Source is a plain textarea, not a second editor.** It shows the buffer's exact markdown, monospaced at the stored note size on the paper and ink tokens. Every input goes through the same `applyDirty` path the block surface uses, so autosave, the unmount flush and the conflict hash check are one path; `note.write` stays the one write and the renderer gains no CodeMirror dependency. The programme retires the committed bundle and trims weight (UI-22, UI-24), and a textarea's selection is already a document offset.
- **The switch carries one document offset.** The departing surface reports its caret as an offset into the note (Source's `selectionStart`; the block surface's selection mapped through the block's source bytes), and the arriving surface places it and scrolls it into view. A pure resolver walks UI-17's parts accumulating source lengths: a block offset yields that block and its block-relative offset, a gap offset lands at the next block's start, past the last lands at the last block's end, before the first at the first block's start, and an empty document yields no selection. The block surface clamps an offset in a heading's hashes or a fence's info line to its nearest editable position. A switch with unsaved edits flushes through `saveNote` first and changes the mode only when that save lands; a conflict freezes the switch and the existing banner is the way out, and a save in flight is awaited rather than doubled.
- **UI-27 (2026-11-10): the note size is header chrome.** `A− size A+` sits beside the mode group, reads and writes `tandem.bikeshed.font-size` through `clampEditorFontSize` on a 1 px step, and the note's size reaches both Write and Source through `--tandem-editor-font-size` set once on the wrapper they share; the chrome keeps its literal sizes.
- **[ADR 0012](0012-editor-formatting.md): the inline live preview is no longer the primary path.** The page this record describes remains the editor until UI-22, and its toolbar and font-size work stand, but the editor's destination is a block surface over the same file. The dated pointer sits on ADR 0012; its history is not rewritten.
- **[ADR 0037](0037-one-stack-rust-core-electron-ui.md): the CM6 bundle is no longer the reason the UI is a webview.** The renderer and its block editor are the reason the shell is Electron. The rest of ADR 0037 stands, and its dated pointer names this record.

## Consequences

- UI-18 imports the model and the save seam and edits a block without re-plumbing the note buffer. The model's block types are the surface's vocabulary, and `editBlock` is the one mutation that marks a block edited.
- No Rust change, no wire change and no CLI verb. The renderer gains no filesystem access; the only path to a real note folder is the read-only sweep script, which a human runs by hand.
- The editor's dialect is now the renderer's parser. Two parsers read markdown (the core's for the ticket sheet, the renderer's for the editor), and the corpus gate is what keeps the editor's side honest.
- A save that cannot serialise is visible: the model throws, `saveNote` returns the error outcome, and the banner shows it. Nothing is written.
- The corpus is synthetic and small. The repository's own markdown and a by-hand vault sweep widen the evidence without committing a human's notes.
