# The agent face is a CLI, not an MCP server

[ADR 0001](0001-store-protocol.md) fixed the store protocol and [ADR 0003](0003-distribution.md) decided how agents reach it: an MCP stdio server, `tandem-mcp`, shipped **inside** the app bundle and reached at its in-bundle path, exposing three tools — `list`, `add`, `complete` — whose descriptions are specified verbatim as *"the agent's only documentation"* (`.scratch/tandem/spec.md`, `.scratch/tandem/issues/03-mcp-tool-contracts.md`). `.scratch/tandem/map.md` cut the alternative on purpose: *"CLI adapter for non-MCP agents or shell scripting — the MCP server is the agent surface."* We decided: **the MCP server retires and a command-line binary, `tandem-cli`, becomes the agent face.** It ships in the app bundle and is reached at its in-bundle path exactly as `tandem-mcp` is today; it links TandemCore and writes the store **directly**, under the same sidecar lock the app takes; it is **agents-only**, with one output path (store-schema JSON on stdout, the short actionable text on stderr); its grammar is namespaced (`tandem-cli todo list|add|complete`, `tandem-cli note rename`); and the tool descriptions move **verbatim** into a `tandem` skill that owns the contract.

## Why the protocol was never the problem

- **The wipe was a stale writer, not a bad protocol.** On 2026-10-17 a long-lived `tandem-mcp` — an old image, still running after `/Applications/Tandem.app` had been replaced — read an unknown `version` as corrupt and then re-encoded the file with its own old shape, losing real data. An MCP server is spawned once per agent session and lives for the whole session, so it is the only component in the system that can be *arbitrarily old while holding write access to the only copy*. That is a property of the deployment, not of Model Context Protocol.
- **A CLI is fresh by construction.** It is resolved from disk at each invocation and dies with it: the binary *is* the installed build, so an upgrade cannot leave a stale writer behind it. This is why the decision is a CLI and not "an MCP server that is more careful".
- **One home for the descriptions.** They are specified as the agent's only documentation. Two faces would mean maintaining that text twice; with one face it lives in the skill.
- **What is given up, knowingly.** Discovery moves from the protocol handshake into the skill, and per-tool permission allowlisting becomes a coarser shell grant. We accept both: the skill carries the same text, and the agent-surface discovery was never the reason agents were allowed to write the list.

## Why the CLI writes directly, not through a socket to the app

- **The staleness problem is already solved by the CLI's shape**, so IPC would buy nothing and add a failure mode: *the app must be running* for an agent to file a todo.
- **The lock still earns its keep.** This is **not** a move to a single writer: the app and a CLI invocation are two processes that can write at once, so the sidecar `flock` ([ADR 0001](0001-store-protocol.md), [ADR 0007](0007-locked-directory.md)) stays exactly as it is. Nothing in this decision weakens the case for `LockedDirectory`.
- **Dev builds stay safe for free.** The CLI inherits `TandemHome` ([ADR 0001](0001-store-protocol.md), "Dev builds get their own home"), so a from-source `tandem-cli` writes `~/.tandem-dev` and cannot reach the real list — the same guarantee `tandem-mcp` has today.

## Why the commands stay off `PATH`

- **ADR 0003's premise is wrong and is corrected here.** It says *"A cask cannot install binaries onto `PATH`; the formula was the only mechanism."* A cask can: the `binary` stanza (and `command_wrapper`) links a file into `$(brew --prefix)/bin` at install and removes it at uninstall. The impossibility was doing the work of a preference.
- **The preference is still right, so the conclusion stands on its own merits.** The in-bundle path is stable across upgrades, needs no cask change, keeps agent setup a single copied line, and avoids compounding the name collision with Homebrew core's `tandem` cask (tandem.chat).
- **The binary cannot be called `tandem`.** The build products `Tandem` and `tandem` are one file on a case-insensitive filesystem, so the CLI ships as `tandem-cli` — a name ADR 0003 already floated with different intent ("a thin `tandem-cli` formula if it ever matters"). The command callers type is `tandem-cli`; the namespaces (`todo`, `note`) carry the meaning, not the binary name.

## Why notes get exactly one verb

- **The filesystem is the notes interface by design.** The bikeshed is "a plain folder of notes" shared by the app, the human, and agents ([ADR 0004](0004-vault-protocol.md)) — GLOSSARY's **Bikeshed**. ADR 0004's lock is one-sided *by design* and names the reason: agents write files directly. `.scratch/bikeshed/spec.md` says it plainly: *"MCP note tools — the agent surface is the on-disk files."* A note CLI would be a second way in over an interface that is deliberately the file itself.
- **Cost was never the argument.** Every bikeshed operation is already public on `Bikeshed` and safe for a one-shot process — readers take no lock, writers take the sidecar lock themselves, nothing needs a running app or a prior index. Any verb would be a thin adapter. The real cost is **ambiguity**: the skill would have to say, verb by verb, when to use the CLI and when to use the file tools.
- **`rename` passes the test the others fail.** It is the one operation whose semantics exceed the filesystem: it rewrites every wikilink that resolves to the note — bare, qualified, aliased, and `#fragment` forms, in every note including itself — in one locked transaction ([ADR 0005](0005-wikilink-rename-rewriting.md)). A raw `mv` does the move and silently shreds the graph, and no amount of care from the agent can reproduce the rewrite.
- **`create` is a rule, not a verb.** The filename grammar (`#` and `|` are the fragment and alias separators; hidden components and non-`.md` names are rejected) *is* a real invariant the file tools cannot protect. But the blast radius is one file and the repair is renaming it, so it belongs in the skill as a rule: never `#`, `|`, or a leading dot in a note filename.
- **`write` and `delete` are out.** The agent's own file tools already write, and the app's conflict detection is built for external writers; `delete` in the core is permanent (only the GUI wraps a Trash move) and rewrites no links, so it would be `rm` with more typing.
- **This reverses a scope cut, narrowly and on the record.** `.scratch/bikeshed/spec.md`'s "the agent surface is the on-disk files" now holds for every notes operation but `rename`, and ADR 0004's clause (b) — the lock "in case MCP note tools ever return" — is answered by a CLI that takes the same lock, not by note tools.

> **Amended 2026-10-18 ([ADR 0016](0016-note-capture.md)):** the `note` namespace is now **two** verbs — `rename` plus `capture`, the raw memory-note write whose naming and queue invariant the filesystem cannot own. Everything below still governs `create` / `write` / `delete`, which stay out.

## Rejected

- **Keep the MCP server.** The stale-writer class is structural to a per-session server, and it already cost real data once.
- **Ship both faces.** Two agent contracts to keep in step, and the verbatim descriptions would live in two places — the drift this change exists to remove.
- **Make `tandem-mcp` a thin shim over one canonical writer.** The smaller change, and it does close the stale-writer hole; rejected because it keeps the MCP SDK, the handshake, and a second contract to describe, to buy discovery the skill provides anyway.
- **A socket to the running app.** Buys nothing over a direct write (see above) and makes the agent surface depend on the GUI being open.
- **A `PATH` entry via the cask's `binary` stanza.** Possible, unnecessary: one more install surface, and a second name to keep straight against core's `tandem`.
- **A full notes CLI** (`new`/`read`/`append`/`search`/`backlinks`/`links`), and specifically `note create`, `note write`, `note delete` — see above.
- **Put the descriptions in `--help` as well as the skill.** Two homes again; `--help` carries syntax only.

## Consequences

- `tandem-mcp`, `Sources/tandem-mcp/ToolDefinitions.swift`, the `swift-sdk` (MCP) package dependency, the `tandem-mcp` build and verify lines in `.github/workflows/release.yml`, and `make-app-bundle.sh`'s second argument all retire.
- The verbatim descriptions move into `skills/tandem/` **from `ToolDefinitions.swift`, not from the spec**: the spec's copy still says "creation order" (superseded by [ADR 0006](0006-stored-order-and-sections.md)) and omits `section`.
- `skills/tandem-memory/` is re-pointed in the same change: its four MCP mentions (`SKILL.md` ×2, `CONVENTIONS.md`, `READ-PROTOCOL.md`, `WRITE-PROTOCOL.md`) become CLI calls for open threads, opening one, and closing one.
- The release workflow's "launches and exits cleanly on stdin EOF" check — a descendant of the retired formula's `brew test` — is replaced by CLI assertions: no arguments prints usage to stderr and exits `2`; `--help` exits `0`.
- The README's two MCP config blocks become the skill install lines. opencode needs none (`~/.config/opencode/opencode.json` already lists `~/projects/tandem/skills`); Claude Code needs `~/.claude/skills`, which does not exist on this Mac yet.
- **The skill ships in the repo and stays there.** Agent skills are distributed as repo directories — that is where they are found — so the CLI installs from the app while its contract installs from a checkout. The two therefore have different upgrade stories on purpose: the binary is signed and versioned with the app; the skill text is reviewed in git like the rest of the docs. Burying it in the bundle was considered and rejected as the non-standard shape.
- **The store is untouched** — no file format, no version, no GUI change — so this rides any release with no version-bump hazard and no rebuild-then-install ordering. The sidecar lock is unchanged and still needed.
- `GLOSSARY.md`'s **MCP server**, **Agent**, and **Filter** entries are rewritten when the CLI lands, not before (until then the glossary would describe a surface that does not exist).
- The live planning docs under `.scratch` get superseded/amended pointers: `tandem/spec.md`'s MCP section, `tandem/map.md`'s scope cut, `bikeshed/spec.md`'s "the agent surface is the on-disk files" line, `bikeshed/map.md`, `distribution/spec.md`'s in-bundle MCP server, and — found while sweeping for stragglers — `tandem-memory/spec.md`, `tandem-memory/map.md` and `tandem-ui/map.md`, each of which names the retired tools or the retired surface as current. Dated tickets under `issues/` and `research/` are records of what was true then and are left as they are.
- Candidate 5 of the untracked `architecture-review.html` is **declined**, on a premise the review got wrong: it calls this boundary logic untested, but `Store.list(rawFilter:)` (`OperationsTests.swift`), `StoreEncoding` and `tandemErrorText` (`RecoveryTests.swift`) are all covered by `TandemCoreTests`, which `Package.swift` declares as the single test seam. Moving any of them into `tandem-cli` would put tested behaviour in a target the tests cannot reach — or force a second test target against an executable's top-level code — so the core keeps them and the CLI **calls them unchanged**. The CLI consequently adds no boundary logic of its own: it is a pure adapter, and this decision changes no behaviour anywhere. Its only edits outside the new target are comments: the doc comments across `TandemCore` and the GUI that name MCP as the *current* caller (`Operations.swift`, `Filter.swift`, `Encoding.swift`, `Errors.swift`, `Store.swift`, `Todo.swift`, `OperationResult.swift`, `Ordering.swift`, `TandemHome.swift`, `StoreWatcher.swift`, `Model.swift`, `LigneControls.swift`) are re-pointed to the CLI, and one test's sample binary path becomes `tandem-cli`.
- The quarantine strip already documented for the app (`xattr -dr com.apple.quarantine`) covers the in-bundle CLI for the same reason it covered the in-bundle MCP server.

Amends [ADR 0003](0003-distribution.md) — the in-bundle agent binary stays, its "a cask cannot install onto `PATH`" premise is corrected, and the MCP server it shipped is retired. Supersedes the agent-surface scope cut in `.scratch/tandem/map.md` and the MCP-server sections of `.scratch/tandem/spec.md` and `.scratch/distribution/spec.md`.
